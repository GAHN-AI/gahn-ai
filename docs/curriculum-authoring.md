# Course sequence authoring

Courses are assembled on the server in `lib/courses.ts`. Content lives in the software, business, specialist, learning and school unit files. Each row has four pipe-separated fields: a stable unit key, a section title, semicolon-separated lesson skills, and a specific practical task. The builder appends a practice entry and a section understanding check. Career pathways end with the role's authored capstone. This compact storage format does not replace pedagogical review.

The course list contains 41 careers, 32 school subject/grade plans and 24 other-world topics. Career sequences range with the role's actual breadth; a support or study-skills pathway does not inherit the length of a full software-development pathway. Do not add generic entries just to match a reference course's lesson count. Do not claim fixed hours or guaranteed completion dates without teaching and assessment data.

A detailed outline is not a completed textbook or an assessment bank. Future AI instruction must develop accurate worked examples and grade actual attempts against each objective. The live session contract documents those requirements.

## Reference framework

These original sequences use common prerequisite relationships and the product's existing role requirements. They are not copies of Udemy lessons and do not claim accreditation, employer endorsement, or universal standards alignment.

- [MDN Curriculum](https://developer.mozilla.org/en-US/curriculum/) and [core modules](https://developer.mozilla.org/en-US/curriculum/core/): web foundations, semantics, CSS, JavaScript, accessibility and tooling.
- [Common Core mathematics standards](https://www.thecorestandards.org/wp-content/uploads/Math_Standards.pdf): a reference for arithmetic, algebra, geometry, statistics and high-school prerequisites. School sequences still need adaptation to the learner's syllabus.
- Authoring includes source evaluation, uncertainty, documented practice, corrections and independent explanation. Sources for current professional rules and software-specific instructions must be checked when instruction is generated.

## Editing policy

Keep unit keys and lesson positions stable within a published course version. Verify that reused units are prerequisites or useful applications for that role. Review subject progression, not just row counts. Run the curriculum and tutor checks after changes. Changes to versioned content need a version or migration decision before resuming existing learners.
